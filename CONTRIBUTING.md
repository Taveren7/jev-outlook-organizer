# Contributing

Use Node.js 22.13+; CI uses Node.js 24. Install with `npm ci`, then run `npm test`, `npm run typecheck` and `npm run test:runtime`.

Keep examples synthetic. Never attach mail content, actual credentials, tenant/account IDs, private audit exports or a populated `.env` to an issue or pull request. A sanitized error code, command name and reproduction using synthetic messages are useful.

Preserve paused startup, preview-before-apply onboarding, mailbox scope checks, conditional category writes, current-state verification and read-only reconciliation after uncertain outcomes. A passing mocked test is not evidence of classifier accuracy or real Outlook display behavior.

For configuration changes, test both custom choices and collision/invalid-input rejection. For changes to the writer or queue, test pause, concurrency, failures and persistence. The default profile is a business example; broader examples and clearer onboarding are welcome.
